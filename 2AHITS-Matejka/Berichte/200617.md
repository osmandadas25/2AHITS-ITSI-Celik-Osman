# Hex Dump

```
Ausgabe in Binär mit xxd: echo -n "ß" | xxd -p -b
Ausgabe in Hexdump mit xxd: echo -n "ß" | hexdump -b

Octet: Folge von genau 8 Bits
Entspricht heute meist einem Byte, aber präziser
Octet ist eindeutig: immer 8 Bit.

Netzwerkprotokolle müssen plattformunabhängig und eindeutig sein.
Daher verwenden Standards wie die der Internet Engineering Task Force oft „octet“, um Missverständnisse zu vermeiden.

xxd -E: Ändert die Zeichenkodierung in der rechten Spalte von ASCII auf EBCDIC. Die hexadezimale Darstellung bleibt unverändert. Die Option ist in Kombination mit -r, -p oder -i wirkungslos. Ist heutzutage nicht mehr relevant, da EBCDIC nicht mehr verwendet wird.

%x: Ausgabe als Hexadezimalzahl (Basis 16), Kleinbuchstaben a-f
8: mindestens 8 Stellen
fehlende Stellen werden mit führenden Nullen aufgefüllt

printf "%.8x" 65534
echo -n "0000fffe" | xxd -r -p
> data.bin
```

**Erklärung:**
```
Die Zahl 65534 wird zuerst als 8-stellige Hexzahl dargestellt (0000fffe). Danach wandelt xxd -r -p diese Hexzeichen in echte Binärbytes um und speichert sie in einer Datei. Dadurch entsteht eine Datei, die den 32-Bit-Wert als 4 Byte im Speicherformat enthält.
```
**Wieder als Dezimalzahl auslesen:**
```sh
od -An -t u4 --endian=big data.bin
-An: keine Adressen ausgeben
-t u4: als unsigned 4-Byte Integer
--endian=big: Bytes als Big Endian interpretieren
```

# Windows Editor

### Ausgabe von "cat UTF-8.txt": äüöÄÜÖß€ 
### Ausgabe von "cat ANSII.txt": 0
### Standard ist UTF-8

### (hexdump nicht installiert, stattdessen xxd -p -b)

```
Bei UTF-8 benötigen Ö und ß jeweils 2 Bytes und € sogar 3 Bytes. Bei ANSI hingegen werden alle Zeichen in nur einem Byte ausgegeben.
UTF-8 ist eine Unicode-Kodierung und kann praktisch alle Schriftzeichen der Welt darstellen. Deshalb benötigen Sonderzeichen oft mehrere Bytes.
ANSI / Windows-1252 verwendet nur 1 Byte pro Zeichen und hat eine feste Zuordnung für die europäischen Sonderzeichen. Daher sind Ö, ß und € dort jeweils nur ein Byte lang.
```

```sh
Ausgabe Windows: 
00000000: 01001000 01100001 01101100 01101100 01101111 00001101  Hallo.
00000006: 00001010 01011010 01100101 01101001 01101100 01100101  .Zeile
```

```sh
Ausgabe Linux: 
00000000: 01001000 01100001 01101100 01101100 01101111 00001010  Hallo.
00000006: 01011010 01100101 01101001 01101100 01100101 00001010  Zeile.
```

### Linux verwendet ein einzelnes Line Feed (LF)-Zeichen (\n), um das Ende einer Zeile zu kennzeichnen, während Windows einen Carriage Return gefolgt von einem Line Feed (CRLF) (\r\n) verwendet

```sh
ANSI Datei in UTF-8 konvertieren:
iconv -f CP1252 -t UTF-8 ANSI.txt > UTF-8_2.txt
```

### Die Konvertierung war erfolgreich, die Ausgabe von xxd -p -b ist bei Original-UTF-8 Datei und der konvertierten UTF-8 gleich

### Vereinfacht gesagt ist Latin-1 (ISO-8859-1) ein standardisierter Zeichensatz für westeuropäische Sprachen, während ANSI unter Windows meist eigentlich Windows-1252 bedeutet.

### Beide sind fast identisch, aber Windows-1252 belegt die Bytewerte 128–159 (0x80–0x9F) mit zusätzlichen Zeichen wie €, typografischen Anführungszeichen („ “) oder dem Gedankenstrich (–). In Latin-1 sind diese Werte dagegen Steuerzeichen und keine druckbaren Zeichen.

### Deshalb funktioniert ein Text, der in Windows-1252 gespeichert wurde, oft nicht korrekt, wenn er fälschlicherweise als Latin-1 interpretiert wird. Das Euro-Zeichen € ist ein gutes Beispiel: In Windows-1252 hat es den Wert 0x80, in Latin-1 existiert es gar nicht.


# Windows JPEG/Exif

### Die Exif-Daten sind als Sammlung von Tags organisiert. Jeder Tag besitzt eine eindeutige ID und speichert Informationen wie Kamerahersteller, Aufnahmedatum oder Belichtungsparameter. Die Daten sind in verschiedene Bereiche (IFDs) gegliedert, z.B. für allgemeine Bildinformationen, Kameraeinstellungen und GPS-Daten. Mit dem Programm exiftool lassen sich diese Metadaten aus JPEG-Dateien auslesen und analysieren.


```sh
exiftool HandyFoto.jpeg
(jetzt exiftool -Make -Model -DateTimeOriginal -ISO -ExposureTime -FNumber -GPSLatitude -GPSLongitude FotoHandy.jpeg, damit die Ausgabe nicht so lang ist)
```

